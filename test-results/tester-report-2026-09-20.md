## หมายเหตุเรื่องข้อจำกัดของเครื่องมือทดสอบ (ไม่ใช่บั๊กของระบบ)

1. **Playwright MCP ไม่มีอยู่จริงในสภาพแวดล้อมนี้** ต้องใช้เครื่องมือเบราว์เซอร์อัตโนมัติอีกตัวที่ทำงานเทียบเท่ากันแทน (คลิก/พิมพ์/อ่าน DOM ผ่านเบราว์เซอร์จริงเหมือนกัน)
2. **แคช HTTP เก่าของเบราว์เซอร์ทดสอบ**: การพิมพ์ URL ตรง (เช่น `leave-requests.html`) หรือคลิกลิงก์ที่ชี้ไปหน้านั้น บางครั้งเจอ 404 เพราะเบราว์เซอร์ทดสอบมีแคชเก่าค้างอยู่ (อาจมาจากช่วงก่อนที่ `npx serve` จะพร้อม) ตรวจสอบแล้วด้วย `curl` ตรงไปที่เซิร์ฟเวอร์และด้วย `fetch(..., {cache:'no-store'})` จากในหน้าเว็บเอง ยืนยันว่าเซิร์ฟเวอร์ตอบ 200 ถูกต้องเสมอ แก้ปัญหาชั่วคราวด้วยการเติม query string กันแคชตอนนำทาง (`?_t=...`) ไม่กระทบกับผลทดสอบ
3. **Native JavaScript dialogs (`alert`/`confirm`/`prompt`) ถูกปิดใช้งานในเบราว์เซอร์ทดสอบ**: `confirm()` คืนค่า `false` อัตโนมัติเสมอ (เหมาะกับการทดสอบว่า "ค่าเริ่มต้นต้องไม่ลบ/ไม่เปลี่ยนสถานะ" อยู่แล้ว) แต่ `prompt()` กลับโยน error แทนที่จะคืนค่า `null` ทำให้เห็น `Uncaught prompt() is not supported` ใน console ตอนกดปุ่ม "แก้ไข" ในหน้าประเภทการลาครั้งแรก — เป็นข้อจำกัดของเบราว์เซอร์ทดสอบเท่านั้น ผู้ใช้จริงบนเบราว์เซอร์ปกติจะเห็นกล่อง prompt ตามปกติ ยืนยันแล้วว่าฟังก์ชันเบื้องหลังทำงานถูกต้องโดยการ override `window.prompt`/`window.confirm` ชั่วคราวเพื่อทดสอบ flow ที่กดยืนยันจริง
