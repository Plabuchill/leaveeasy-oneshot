## Test 5 — ล็อกอินบัญชีที่สองแล้วเปิดใบลาของบัญชีแรก (per-owner isolation) — คาดว่าจะล้มเหลว และล้มเหลวจริงตามคาด

> **บริบทสำคัญ:** ตามสเปคหัวข้อ 8 การจำกัดสิทธิ์แบบ "ผู้ขอลาคนหนึ่งเปิดใบลาของผู้ขอลาอีกคนไม่ได้" (US-08 ข้อสุดท้าย) เป็นงานของ **สัปดาห์ที่ 8** (Security Rules รายห้อง) โค้ดปัจจุบัน (สัปดาห์ที่ 7) มีแค่กฎขั้นต่ำ "ต้องล็อกอินก่อน" เท่านั้น ยังไม่แยกสิทธิ์ตามเจ้าของ ดังนั้นผลด้านล่างคือ **"ช่องว่างที่ทราบอยู่แล้วและยอมรับได้ในสัปดาห์นี้"** ไม่ใช่บั๊กที่ต้องรีบแก้ — บันทึกไว้เป็น baseline เพื่อนำมาทดสอบซ้ำหลังสัปดาห์ที่ 8 เสร็จ

**ขั้นตอนที่ทำจริง:**
1. สมัครบัญชีที่สอง `tester-agent-2-1789895669@example.com` (ชื่อ "Tester Agent Two")
2. ล็อกอินด้วยบัญชีที่สอง
3. Navigate ตรงไปที่ `leave-request-detail.html?id=F8KVdMdC5mtsdKIVtBli` (ใบลาที่บัญชีแรกสร้างใน Test 1)
4. ยิง raw REST call อ่านเอกสารนั้นโดยตรงด้วย ID token ของบัญชีที่สอง

**ผลที่ได้จริง:**
- [ ] **หน้าเว็บแสดงข้อมูลใบลาของบัญชีแรกให้บัญชีที่สองเห็นครบทุกช่อง** (หัวข้อ เหตุผล ผู้ขอลา สถานะ ฯลฯ) — เปิดดูได้ปกติเหมือนเป็นเจ้าของเอง
- [ ] raw REST call ด้วย ID token ของบัญชีที่สอง (`GET .../documents/leaveRequests/F8KVdMdC5mtsdKIVtBli` พร้อม header `Authorization: Bearer <id token ของบัญชี 2>`) **ได้ผลลัพธ์ 200 OK และคืนข้อมูลเอกสารเต็ม** (title, reason, requesterName ฯลฯ) — ไม่ถูกปฏิเสธ

**สรุปสถานะปัจจุบัน:** ยืนยันแล้วว่า **ยังไม่มีการแยกสิทธิ์ตามเจ้าของใบลา** ทั้งฝั่งหน้าเว็บและฝั่ง Security Rules จริง ตรงกับที่คาดไว้ว่าเป็นงานของสัปดาห์ที่ 8 **ไม่ถือเป็น FAIL เร่งด่วน** — บันทึกไว้เป็นเทสต์ baseline ให้รันซ้ำอีกครั้งหลังใส่กฎรายห้องของสัปดาห์ที่ 8 แล้ว คาดหวังผลในตอนนั้นคือ 403/ปฏิเสธ

## บั๊กที่พบ (เรียงตามความรุนแรง)

ไม่พบบั๊กที่เป็นของจริงในแอปจาก 5 เทสต์นี้ ทุกอย่างเป็นไปตามเกณฑ์การยอมรับของสัปดาห์ที่ 6-7 ที่สร้างเสร็จแล้ว ยกเว้นช่องว่าง Test 5 ที่รู้อยู่แล้วว่ายังไม่ถึงกำหนด

หมายเหตุเรื่องเครื่องมือทดสอบ (ไม่ใช่บั๊กของแอป แจ้งไว้เพื่อความโปร่งใส):
1. ระหว่างทดสอบพบว่ามีอีก browser session หนึ่งแชร์ viewport เดียวกันอยู่ (ข้อความ "another Claude session set this" ปรากฏหลายครั้ง) ทำให้บางจังหวะการคลิกตามพิกัดคลาดเคลื่อนและต้อง re-screenshot ก่อนคลิกใหม่ — แก้ปัญหาได้ทุกครั้งด้วยการถ่าย screenshot สดก่อนคลิก จึงไม่กระทบผลสรุปของเทสต์
2. เห็น console error ปลีกย่อยที่ไม่เกี่ยวกับขั้นตอนของฉันโดยตรง เช่น `prompt() is not supported` จาก `js/leave-types.js:66` และ 404/400 ประปราย — คาดว่ามาจาก session อื่นที่แชร์เบราว์เซอร์เดียวกันกำลังทดสอบหน้า `leave-types.html` (ฟีเจอร์แก้ประเภทใช้ `prompt()` ซึ่งแซนด์บ็อกซ์เบราว์เซอร์ไม่รองรับ) จึงไม่ได้นำมานับเป็นบั๊กในรายงานนี้เพราะไม่ได้เกิดจากขั้นตอนทดสอบ 5 ข้อของฉันเอง — ถ้าต้องการตรวจ US-06 (จัดการประเภทการลา) จริงจัง ควรทดสอบแยกรอบใหม่
